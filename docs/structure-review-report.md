Krishnamurthi's worked Java example shows the choice has concrete, observable consequences. No participant contests that structural-vs-nominal is a real, load-bearing axis in the domain, and challenger-b found no defect in the carve's sourcing, layer placement, or atomization.

The challenge that is upheld is narrower and structural: the carve's `exclusivity: exclusive` combined with `applies_to: ['general-purpose']` asserts one value of the axis per whole language, but the cited evidence (Sebesta §6.15 on C: name equivalence for struct/enum/union, structure equivalence for arrays, plus a file-boundary exception; Sebesta on Ada: structure equivalence for unconstrained arrays alongside three different strictness levels of name equivalence for derived types/subtypes/anonymous types) shows real languages mixing the two mechanisms by type-construct category within a single language. The proposer, after searching, could not locate a Pierce passage actually backing the language-level-exclusive framing attributed to him in the note, which removes the strongest piece of support for that framing. This is a genuine mismatch between what the ontology's per-language exclusive-value slot can express and the grain at which the evidence actually varies — a dimension-model gap, not a flaw in the carve's identification of the axis itself.

Per the handling rule for upheld wrong-structure challenges, the carve is kept on its own merits (the axis is real and well-evidenced) while the structural gap is flagged for the structure review: the dimension-model needs either (a) a `mixed`/`combination` value usable alongside `structural`/`nominal` for languages whose construct categories differ, or (b) a way to scope `exclusivity` at a grain finer than "per language" — e.g., per type-construct category (record/struct, array, enumeration, etc.) — since that is the granularity at which C and Ada's documented behavior actually resolves to a clean exclusive choice. Until the dimension-model is extended with one of these mechanisms, any carve using whole-language `exclusivity: exclusive` will misclassify languages, like C and Ada, that mix rules by construct — so the challenger's underlying objection about accuracy for those languages remains live even though the carve itself is not being altered here.
  [01 typing] dynamic-typing: Both challengers' citations check out against the record, and the proposer's own final-round review (checking Van Roy & Haridi §2.3.2 directly) found the problem is worse than first alleged. Three distinct, evidence-backed problems survive: (1) the carve's `note` asserts static/dynamic typing are "the other exclusive value of the same discipline-time axis," but Harper formally argues the opposite — "every dynamic language is inherently a static language in which we confine ourselves to a (needlessly) restricted type discipline" [harper-pfpl#c00346] and "this traditional distinction can hardly be considered an opposition" [harper-pfpl#c00343], with Hybrid Typing (§24) building a language where the two "coexist harmoniously" as containment ("dynamic typing is a mode of use of static typing") rather than alternation. Van Roy & Haridi corroborate non-exclusivity independently, though via a continuum framing rather than Harper's containment framing: "the choice... does not have to be all or nothing... a bit of the other can be added" [vanroy-haridi-2003#c00239]. This is a dimension-modeling problem, not a problem with the node's existence. (2) The carve's defining criterion — "values, not program phrases, carry type information" — is the literal target of Harper's §24.4 rebuttal of the three "supposed distinctions," which argues value-tagging "amounts to a use of recursive sum types within a statically typed language, and hence cannot be seen as a distinguishing feature" [harper-pfpl#c00371]. Presenting this as settled textbook consensus rather than a contested criterion from one of the carve's own cited authorities misstates the literature. (3) The evidence trail is internally inconsistent: arguments made for this carve treat Van Roy & Haridi as confirming the value-tagging formulation, but that source's own definition is binding-time-based — "the variable type is known only when the variable is bound" [vanroy-haridi-2003#c00153] — which is exactly the "related but separate concept" the note excludes. The node itself is sound and well-attested (Turbak/Gifford, Scott, Harper's own DPCF operationalization all treat it as a real, nameable discipline even under Harper's degenerate-case account), so this is a revise, not a drop or escalate — the disagreement is about framing and boundary-drawing, which the evidence resolves clearly enough to act on now.
  [01 typing] parametric-polymorphism: The parametric-polymorphism node itself is solidly evidenced: Pierce §23.2's definition of uniform generic instantiation [pierce-tapl-2002#c00726] matches the carve's summary almost verbatim, and Cardelli & Wegner, Sebesta, and Scott independently converge on the same definition and the generics/generic-subprogram alias. `realizes: ['polymorphism']` is well supported and uncontested. The `wrong-structure` challenge is upheld on its merits. Two problems are independently sourced: (1) Cardelli & Wegner's own classification is two-tiered — "parametric and inclusion polymorphism are classified as the two major subcategories of universal polymorphism, which is contrasted with nonuniversal or ad-hoc polymorphism" [cardelli-wegner-1985#c00011] — so a flat `dimension` with parametric/ad-hoc/inclusion as co-equal members drops the intermediate "universal polymorphism" node that is the actual organizing move of the cited taxonomy. (2) Pierce explicitly denies the exclusivity a single-select `dimension` axis implies: "These categories are not exclusive: different forms of polymorphism can be mixed in the same language. Standard ML offers both parametric polymorphism and simple overloading... Java includes subtyping, overloading, and simple ad-hoc polymorphism... but not... parametric polymorphism" [pierce-tapl-2002#c00728]. A dimension model that assumes one value per axis misrepresents a freely-combinable, hierarchical classification as a partition.

This is a structural gap, not a defect in the node: the `dimension-model` structural element currently has no way to express either (a) hierarchical/nested classification axes, or (b) non-exclusive, co-occurring membership. To hold this carve's `dimension` assignment, the structure would need to either support an intermediate dimension-bearing node (e.g., a `universal-polymorphism` parent carrying `parametric-polymorphism` and `inclusion-polymorphism` as children, sibling to `ad-hoc-polymorphism`) or abandon the single-select-axis semantics for this case and drop `dimension`/`cross_cutting` from this node entirely, letting `realizes` alone carry the relationship. The proposer identified both options but had no evidentiary basis to choose between them, so that choice belongs to the structure review rather than to this node-level carve. The node's own fields (id, name, summary, evidence, aliases, realizes) should stand as drafted pending that structural ruling.

Both wrong-structure challenges are upheld on their cited passages. The sources assert subsumption, not prerequisite dependence: ordinary and generalised data types are two diagnoses of one declaration grammar ([ghc-users-guide#c00689]), an ordinary ADT may be declared in GADT-style syntax ([ghc-users-guide#c00695]), and anything declarable in Haskell 98 syntax is declarable in GADT syntax ([ghc-users-guide#c00683]). Decisively, where the source does state GADTs' prerequisites it names other features — "Implies MonoLocalBinds, GADTSyntax" [ghc-users-guide#c00693], "A GADT can only be declared using GADT-style syntax" [ghc-users-guide#c00694], and "the combination of GADTSyntax and ExistentialQuantification is enough to define and use GADTs" [ghc-users-guide#c00576] — and `algebraic-data-types` is absent from that list. Under `requires`-as-two-feature-dependency the edge is vacuous or, read as "ADTs are a separate component GADTs call into," contradicted by [ghc-users-guide#c00695]. The proposer's "definitional, not historical" defence is itself an argument for a subsumption relation. Swapping to `influences` would be a worse misreport, downgrading definitional containment to a causal nudge.

What the structure would need to hold this carve: a generalises/specialises (or extends / special-case-of) edge type in the relation inventory, expressing that one feature's mechanism contains another's as its degenerate case rather than depending on it as a coexisting prerequisite. Until that slot exists, this edge is typed `requires` only because `requires` is the nearest available slot, and its statement and its type report different things to any consumer. The ADT/GADT pair is a clean motivating example for the structure review.

[ghc-users-guide#c00695] uses "include contexts" / "bind existential variables" as a diagnostic for whether a declaration is treated as a GADT, not as a content inventory; [ghc-users-guide#c00683] attributes the existential generalisation and the constructor-context behaviour to GADTSyntax, "but not GADTs themselves," demonstrated on an ordinary data type (`MkSet :: Eq a => [a] -> Set a`); and [ghc-users-guide#c00575]/[ghc-users-guide#c00576] decompose the three axes across separately gated extensions.
